# Стилистика кода HelpeRP

Единые правила оформления Python-кода и данных проекта HelpeRP.
Соблюдение этих правил обеспечивает предсказуемость, читаемость и лёгкое
сопровождение.

---

## 1. Синтаксис и типизация

- **Python 3.10+** — используется современный синтаксис объединения типов:
  ```python
  def load_items(path: str) -> list[dict] | None: ...
  ```
  `Optional[...]` из `typing` **не используется** — только `X | None`.
- Используются встроенные дженерики: `list[dict]`, `dict[str, str]`,
  `tuple[bool, str]`, а не `List[...]`, `Dict[...]`.
- В начале модулей, где нужны отложенные аннотации, добавляется:
  ```python
  from __future__ import annotations
  ```
- Возвращаемый тип указывается всегда. Для методов без возврата — `-> None`.

## 2. Именование

| Объект | Стиль | Пример |
|--------|-------|--------|
| Модули | `snake_case` | `json_loader.py`, `rag_search.py` |
| Классы | `CamelCase` | `class AIClient`, `class RagSearcher` |
| Функции/методы | `snake_case` | `filter_and_rank()`, `_resolve_api_key()` |
| Приватные члены | префикс `_` | `_cache`, `_on_filter()` |
| Константы | `UPPER_SNAKE` | `BG_ROOT`, `FACTION_ICONS` |

- Приватные «служебные» методы начинаются с `_` (например `_sort_scored`,
  `_prepare_rgba`).
- Псевдонимы и синглтоны пишутся строчными: `rp_ai = AIClient()`,
  `app_config = Config()`.

## 3. Кавычки и строки

- Строки — двойные кавычки `"..."`. Одинарные — только когда двойные
  встречаются внутри (например текст с `"`).
- f-строки предпочтительны для конкатенации:
  ```python
  label = f"{shown} / {total} {unit}"
  ```

## 4. Docstring и комментарии

- Модульные docstring — в начале файла, кратко описывают назначение:
  ```python
  """Ранжированный поиск по записям баз HelpeRP."""
  ```
- Docstring методов — на русском, однострочные или с кратким описанием
  параметров/возврата.
- Комментарии поясняют «почему», а не «что» (что понятно из кода).
- Комментарии с пометкой бага/оптимизации обязательны, если код исправлялся:
  ```python
  # Внимание: remove_hotkey принимает хэндл, а не строку (была утечка).
  ```

## 5. Импорты

- Порядок: стандартная библиотека → сторонние → локальные (core/gui).
  Между группами — пустая строка.
  ```python
  import json
  import os

  import customtkinter as ctk

  from core.paths import data_dir
  ```
- Импорты внутри функций допускаются только для тяжёлых/опциональных модулей
  (ленивая загрузка) или для избежания циклических зависимостей.
- Используются пакеты с `__init__.py` (`core/`, `gui/`, `data/`).

## 6. Загрузка данных и кэширование

- JSON-базы загружаются через единый модуль `core/json_loader.py`:
  ```python
  from core.json_loader import load_json, load_json_list
  data = load_json_list(path)
  ```
- Ленивая загрузка с кэшем — глобальная переменная + проверка на `None`:
  ```python
  _cache: list[dict] | None = None

  def load() -> list[dict]:
      global _cache
      if _cache is not None:
          return _cache
      ...
  ```
- Сброс кэша — через `invalidate_cache()` (сбрасывает и кэш json_loader).

## 7. Структура модулей

- `core/` — бизнес-логика (без UI): конфиг, поиск, ИИ, лицензии, обновления.
- `gui/` — интерфейс CustomTkinter: окно, панели, темы, иконки.
- `data/` — JSON-базы знаний и генераторы данных.
- `tools/` — dev-инструменты (сборка, релиз, генерация иконок, ключи).
- `assets/icons/` — PNG-иконки (генерируются через `tools/generate_icons.py`).

## 8. Иконки

- Иконки — настоящие PNG с прозрачностью (RGBA), цветные под фракции.
- Загрузка через `gui/icons.py`; готовые CTkImage кэшируются.
- **Не** использовать попиксельную маску «чёрный → прозрачный» — она стирает
  монохромные иконки. Иконки должны приходить уже с альфа-каналом.
- Ретинка: кэшируется крупное изображение (SIZE=64), CTkImage масштабирует.

## 9. Формат JSON-баз

- Файлы в `data/` используют `ensure_ascii=False` и отступ `indent=4`.
- Ключи записей (единый формат):
  `article`, `title`, `description`, `category`, `chapter`, `punishment`,
  `is_frequent`, `usable_by`, `keywords`, `source_faction`.
- Шаблоны (`templates.json`) поддерживают v2.0: `lines`, `variations`,
  `success_outcome`, `fail_outcome`, `advice`.

## 10. Ошибки и надёжность

- Ошибки внешних модулей перехватываются и логируются в консоль с префиксом
  модуля: `[json_loader] ...`, `[Hotkeys] ...`.
- UI-обновления из фоновых потоков выполняются через `root.after(0, ...)`.
- Глобальные хоткеи хранят хэндл (число) от `keyboard.add_hotkey()` для
  корректного снятия биндинга.
